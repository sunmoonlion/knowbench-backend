## 私有专家的递归孵化执行（2026-11-19，开发候选）

本片扩展孵化测试中的唯一计划，仍限本人私有、`allowed_callers=["host"]` 的方法。
每个必做步骤引用一个精确 `MethodRef`，允许引用已真实验证并冻结登记的专家和专家团，
最终叶子仍为零内部模型轮次、经运营核验零新增费用的直接 MCP 工具方法。
`on_failure="fail"`、`max_replans=0`，输入仅支持调用者值、常量和已验收前序产物；
没有可选步骤、分支、多候选、自动资源绑定、动态重规划或暂停后改计划。

本候选沿用旧枚举。目标协议按工具和专家两类收口，M3 同步提供方与消费者。旧协议的方法类别按直接允许依赖的方法 ID 核定，不按版本数、实例数或全部后代累计。
同一专家的两个版本、同一版本在多个分支重复调用仍是一种专家，但每个精确版本必须
各自合格，每次调用都有独立身份。直接引用两种以上专家或已有专家团的归专家团；
专家与专家团使用同一个编排执行机制，不新增团队执行器。

根请求的 dependencies 仍表示直接引用，内部执行快照钉住完整冻结依赖闭包。
受理、每步准备、批准、封存及首次登记重新核对本人归属、真实 host 测试资格、精确版本、
当前来源、执行许可和操作策略。闭包去重不合并实际调用，也不复制出新的注册方法。
局部 DAG 校验与祖先方法循环检查分别进行；每层深度、展开及步骤上限同时受整棵树约束，
全局最多 16 层、1000 次展开和 100 个实际叶子调用，不在进入子专家时重置额度。

整次执行沿用一个 Task、一个当前活跃叶子 Attempt 和既有 Interaction。
共同调用账记录真实的根专家、各层子专家、叶子方法及实际 MCP 派发，直接父调用保持真实层级；
内部身份使用完整步骤路径及摘要，不能靠裸步骤名恢复。中间专家没有伪造的模型轮次或叶子
Attempt，其导出产物使用 `attempt_id=None` 的 Artifact 并绑定自己的方法调用。
子层先验收并完成自己的 exports，父步骤再校验和投影输出，上层成功不由下层技术成功代替。
恢复读取已接受产物的精确版本，并重核叶子 Attempt、实际工具结果、输入绑定及逐层导出，
不读取同名最新产物覆盖历史。

每个外部动作仍由本人核对参数后逐次批准。根授权容器累计绑定精确叶子调用的直授，
叶子的资源授权来源为根调用；真实方法调用父链与授权来源链分别保存。
中间专家仅有空 grants 的执行 scope，不持有资源权限，也不能执行或再次委派叶子的 grant。
共同 `covers`/`delegate` 的收窄规则未放宽，accepted-plan 的资源方一层委派依据不自动成为
正式 MethodRef 的多层委派权。根及中间 scope 的期限固定为已接受测试 run 的创建时间加

丢失或撤销的 scope 不能被恢复流程重建，期限不能自行延长。

取消、持久 scope 撤销、到期和来源失效会阻止未执行动作，关闭相应待批准操作并终止受影响的
未完成调用。已成功的子层结果保留；可能已经派发的 unknown 保留不确定事实，不自动重试或
声称副作用已撤回。重新启动驱动只恢复同一调用身份与既有事实，不绕过失效授权。
独立完成器按批准当时的历史事实核验 scope、父修订与精确 grant，再重算每层绑定、输出和
根导出；当前权限不能倒填历史批准，后续到期也不把过去合法执行改成未发生。

作者提交私有、`allowed_callers=["host"]` 的冻结工作稿与测试集。每步必须有且只有一个

输入支持调用者输入、常量与前序步骤产物，导出必须显式声明。前序结果按 Attempt 所指的
Artifact 精确版本读取，不退回同名最新产物。可选/分支/多候选、重规划、资源自动绑定、
暂停和嵌套专家/专家团不属于本入口。实现沿用原 Task 状态机，每个步骤有独立 Attempt，

根专家调用 → 实际叶子方法调用 → MCP 工具调用都写入共同调用账。同一叶子重复两次，

各步的精确范围，子授权固定父修订，历史批准事件保留双方快照。这不消费上一片的资源方
委派目录，也不表示新 MethodRef 已获得递归委派。用户仍须逐次核对具体动作。

恢复沿持久调用身份推进，不自动重发 dispatching/unknown；未派发步骤的来源失效会关闭
对应待审批动作并使计划失败，已执行事实保留。多次审批等待时长先完整累计再统一取整，
避免小数截断绕过总等待上限。失败、拒绝、取消或未知结果不能取得专家测试资格。

完成器独立核对每步真实调用、输入绑定、产物版本与摘要、审批、父子授权、操作策略和
最终导出，再应用作者测试断言与通过阈值。成功封存和首次登记重新核对全部叶子的当前
资格。真实执行证据使用 `knowbench/formal-orchestration-host/v1`，临时测试任务清理后

网页展示精确依赖、绑定和导出，并沿当前动作恢复后续审批，不增加第二套审批历史。

## 资源方依据与一层委派（2026-11-15，开发候选，未发布）

当前普通聊天/工作已支持本人私有、真实验证过相应 host/model 调用来源的方法版本；仍须逐次动作批准。以下较早交付段落按当时范围保留。本次新增的是现有已接受方法计划的资源委派依据，不开放新的正式专家编排或旧作者绑定入口。

方法的声明、用户选择和来源许可证都不能自行授予资源委派权。`WORKBENCH_RESOURCE_DELEGATIONS` 为默认空的运营核验目录，和 `WORKBENCH_SOURCE_LICENSES` 分开：前者描述特定账号资源的一层委派，后者描述实现来源的执行/交付许可。代码检查核验记录的适用范围，不联网判定或自动取得真实资源方授权。

运行中失效沿用停轮、结算并等待重新确认；若在打开 Attempt 后、第一次准备完成前失效，尚无运行范围可写撤权标记，沿用既有准备失败路径：不发送 `turn/start`、费用为零，Task 进入 FAILED。该窗口目前不能在原 Task 直接重新确认后继续，不能将两种恢复行为混写。

记录固定资源责任方 `issuer`、用户 `owner_actor_id`、连接 UUID 与修订、可信操作摘要、完整 `AccessRequirement` 上限、状态、带时区起止和证据引用/摘要。`binding.kind=accepted_plan` 固定父方法 ID、父快照摘要、子方法定义 ID 和版本；它是已有计划的身份，不冒充新正式方法的 `MethodRef`。`max_delegation_depth` 仅接受整数 1。同一记录编号不得重复；不同记录可以供明确选择，但一次权限需求必须由一条记录完整覆盖，不能拼接账号、资源或用途。记录任何内容变化都会改变完整摘要，漏改修订号也不会继续匹配旧引用。

用户在当前方法的“本次能力”中选择账号后，可明确选择服务端提供的资源方依据；默认不选择，继续原有精确直授。选择只上传记录编号、修订及摘要，不接受客户端自行填写委派布尔值、父调用或权限范围。服务端重建已接受计划和真实调用身份，再把依据写入现有 `workbench_method_authorizations`：根范围只向当前精确子调用下传一层，子调用不可继续委派。期限同时受资源记录与原 24 小时确认上限约束。准备、调用、动作批准和恢复均重验当前依据；具体外发/写入仍逐次经过原 Interaction，依据选择不产生动作批准。过时或消失的选项必须明确清除或重新选择，不能自动换成另一份记录。

运行中的依据失效由 runner 写入持久撤权标记，沿既有停止、费用结算和重新确认流程处理。已经成功或结果未知的调用保留，不因撤权声称副作用回滚，也不自动重发。没有真实接受计划的固定步骤和普通会话不能获得此委派入口；新正式专家/专家团的编排与资格仍待后续接入。

配置继续由既有部署配置真源提供，当前未配置任何真实记录。该目录是各进程启动时读取的快照，**修改环境配置不等于即时全局撤权**。需要停止已有授权时，由有权所有者先使用当前“撤销方法权限”流程把撤权写入共享数据库；运营配置的移除/修订须覆盖全部 API、runner 副本，重新确认前核对同一配置版本。不能只更新单个副本后声称全局已生效。本轮不部署、不启动真实供应商或付费模型调用；工程验证使用合成资源方证据。

## 本地 C2 续作（2026-11-15，开发候选，未发布）

正式方法的来源查询、验证受理与冻结登记通过现有 KnowLab 服务身份进入 API，独立于会话安装。来源查询只返回本人安装资产的精确修订及实现摘要；MCP 还须命中运营核定操作，凭据和 Skill 正文不进入此目录。当前没有可信执行许可记录的来源标为 `pending`，作者不能通过提交任意许可文字使它通过。

`formal_methods.py` 的旧验证受理仍只保存静态检查与 pending；新 `formal-method-execution/v1` 入口负责真实测试执行。当前范围仅为 `allowed_callers=["host"]`、零模型轮次、一个精确权限需求的直接 MCP 方法。用例、重复次数、通过阈值、类型化断言、预算、超时和执行电脑由 KnowLab 冻结为不可变测试集；KnowBench 复用既有测试、Task/Attempt、Interaction 和共同调用记录，不转换旧 pack，不制造模型工具事件。断言留在判分端，不进入 Task 输入、执行快照或 MCP 参数。

用户逐次批准具体参数后，宿主建立绑定本次根调用的不可委派直授，再由共同适配器派发。输出必须是 MCP `structuredContent` 对象，逐项符合声明的输出槽；不从任意文本猜测返回结构。调用不随 Attempt 或重启自动重发，失联结果记 unknown。派发中取消只停止后续推进，不声称撤回外部副作用；迟到的真实回执仍留在共同调用记录。

验证完成器重新核对冻结请求、Task/Attempt、调用、批准人及有效期、精确授权和真实输出，并重新判分。满足测试阈值且至少有一次正向执行才能生成带 request/suite/evidence 摘要的回执；已知业务断言失败可按作者明确的重复阈值处理，unknown 不准入。输入拒绝和实际审批拒绝须有可复核事实；只有文字说明的 authorization_denied 尚不能证明全部治理检查。自然语言业务有效性未被这些断言充分覆盖，回执明确记录自用未覆盖范围，不获得公开资格。最小证据保存在正式验证记录，临时测试任务清理前必须先封存；清理后仍可核对冻结登记。

此执行入口暂不支持第三方计费。运营的 `WORKBENCH_CAPABILITY_OPERATIONS` 中，相关操作必须显式提供 `formal_execution_cost`：`incremental_cost="0"`、`currency="CNY"`、无秘密的 `evidence_reference` 和 `sha256:` 格式的 `evidence_digest`。这是运营对“不产生新增调用费”的核验记录，不是供应商声明或作者开关；缺少记录拒绝受理、批准与成功封存，记录变更使旧审批失效。未配置该字段的既有操作不会因此获得正式测试资格。模型预算仍进入既有账本；该宿主路径没有模型轮次。没有填写实际供应商或费用证明，也没有因此开放付费调用。

KnowLab 冻结后经幂等登记接口交付；API 对照自身保存的请求、回执及证据摘要，包含定义、来源、修订、全部候选与 allowed_callers。登记存入 `workbench_formal_methods`，只保存 KnowLab 冻结版本投影；公开资质尚未贯通时拒绝公开登记。来源后续失效不抹去历史登记，实际运行仍须重新核权。此直接 MCP 测试切片不代表正式方法模型派发、专家编排、脚本或平台/KnowBase 资源权限已经贯通。

运行中撤权将停止要求写入当前 Attempt，runner 只中断对应 turn；确认停止并记录计费状态后进入现有 Interaction 等待重新确认权限。重启时仍先确认旧轮已停止；未知费用明确记录，已完成及 unknown 调用保留，未确认停止不能开始新 Attempt。

停轮不得依据空的或分页的 `turns` 列表推断；实际线程状态仍为 active、状态缺失或无法确认时保留阻断。尚未发送 `turn/start` 的准备失败另记未启动事实。费用通知缺失时，终止 Attempt 不等于零费用：保留该 Attempt 尚未消费的预算预留并标记待核对；取得绑定同一轮的完整费用回执后幂等补记和释放，已确认零费用也须有回执。迟到的部分 usage 通知没有最终标志，不自动作为完整账单。

用户确认的权限绑定真实 `recipient_call_id`，不再默认赋予委派资格。同一方法 ID 的后代调用也不能继承该直授。0044 迁移将旧权限原文保留为调用证据，并撤销旧运行授权及待批准动作；有授权数据时拒绝有损回退。0043 新增验证与登记表，有证据时同样要求向前修复。迁移仅在隔离测试库验证，未对线上执行。

超出上述直接 MCP 首片的执行验证器、通用正式方法模型派发、编排路径、完整平台/KnowBase 资源权限及资源方明确委派依据仍待接入。`RunGrant.process="delegation"` 表示业务委托，不代表允许再委派。新作者页面支持定义、测试集、执行状态、逐次审批及冻结；旧受管能力作者入口及脚本开关继续关闭。本节不是 C2 完成或上线声明。

## 评审修复（2026-11-14 已随 #94 发布）

- 没有安装资产、没有历史能力 runtime 且没有活动方法的普通会话走元数据快路径，不新增能力范围、不加资产行锁、不为能力准备调用 `thread/read`。方法场景及曾配置能力的会话继续核对范围。

所有者已明确新开发不要兼容：后续公共机制/C2 改造删除旧执行分支；有实际数据才作一次性迁移，不长期双读双写。2026-11-13 夜三张能力表均为空，相关工作稿/专家草稿/市场版本/委托无方法能力字段。此检查不代表其它旧类型都无人使用，发布前复核。

## 外部操作契约候选（2026-11-14，尚未发布）

外部 MCP 不再仅凭审核 URL、工具发现和用户逐次批准执行。运营配置 `WORKBENCH_CAPABILITY_OPERATIONS` 是可信适配定义的唯一来源；`domain/workbench/tool_operations.py` 校验定义，API 在登记投影、选择、准备、调用和批准派发时消费。MCP annotations、模型参数和用户安装请求不能提供或替换这些权限事实。

每项定义包含以下字段，不含用户凭据或当前批准：

| 字段 | 实际检查 |
| --- | --- |
| `service_url`、`tool_name`、`descriptor_digest` | 精确绑定已审核服务与发现快照；摘要由 `ToolRegistration.discover("mcp", url, descriptor).descriptor_digest` 生成，不是远端实现版本承诺 |
| `capability_ref`、`version`、`operation` | 平台核定的业务操作契约及版本，不以工具名称推测业务含义 |
| `effect` | 只接受 `read`、`write`、`send`；所有操作仍逐次审批，可信只读不等于已获得任务范围授权 |
| `resources[]` | 显式声明资源角色与参数路径；无参数资源时显式 `[]`，不能漏字段 |
| 资源的 `resource_kind`、`resource_role`、`argument_path`、`cardinality` | 当前责任域为 `connector`；路径只逐层取对象字段，终值为一个字符串或非空字符串数组；不执行表达式或通配匹配 |
| 资源的 `allowed_values` | 可选的平台精确值集合上限；省略只表示平台未额外收窄，用户仍须批准具体动作；空集合、重复值和未知条件拒绝 |

例如发送工具的 `to` 参数可绑定为 `{"resource_role":"recipients","argument_path":["to"],"cardinality":"many","allowed_values":["approved@example.test"]}`。必须按服务真实语义核定全部资源字段（包含可能的抄送、密送、查询范围等）；复杂查询、目录层级或别名不能假装成通用精确匹配，需要专门适配。工具名相同不代表适配成立，刷新后的描述摘要变化也须重新核定。

新配置为 JSON 数组，默认 `[]`。端点不在 `WORKBENCH_CAPABILITY_MCP_URLS`、重复绑定、未知字段或不支持的条件均在配置解析期拒绝。配置由原有部署配置真源提供，API 与 runner 同批更新；没有新增管理接口或另一份数据库策略主档。没有操作定义时仍可安装连接、发现工具和保留记录，但不能选用或执行该工具；本次能力显示原因，已选工具可移除。聊天准备排除不可用工具后继续，方法缺必需项则拒绝准备。

准备时冻结操作定义摘要；新调用核真实宿主身份，再解析资源和平台上限，超范围请求不生成审批。实际操作、资源、数据去向及完整参数摘要保存在已有调用记录中并参与原审批摘要。即使是读取，发往服务的查询参数也记录为数据外发。批准前再次核当前定义与精确请求；移除、收窄、扩大或升级定义均使旧批准不能继续执行，仍可拒绝该请求。旧记录缺操作快照不能现场补造后派发。`tools/list` 和 Skill 正文中的已选依赖提示也排除操作定义失效的工具；已有模型上下文无法追溯删除，实际调用仍会拒绝。

这只是 C2 的可信外部操作映射与平台资源上限：**尚未接入方法层 `access_requirements`、父子委派范围、资源端账号权限、任务范围只读授权、平台内置工具的共同业务策略和统一调用账。**逐次审批仍不代替这些后续权限检查；作者入口保持关闭，脚本开关保持关闭。新配置没有部署，真实供应商语义未验收；没有数据库迁移和公开响应结构变更。

## 授权与执行

注册／工具发现、会话选择、模型暴露、操作批准、实际执行是不同阶段。选择保存使用期望修订比较交换，冻结资产版本；资产停用、更新凭据或刷新工具后，旧选择必须重新核对。默认偏好不改变授权版本；刷新不会把新工具加到旧选择。

普通会话的外部 MCP 工具先登记待批操作；方法步骤的外部 MCP 调用和所有包内脚本调用则以 SSE 等待审批及真实结果后返回。工具描述和注解按实际执行语义提供，不把远程写操作标成只读。固定 Codex 的原生批准不替代平台的操作批准。首期所有外部调用（包含读取）都逐次确认。

批准绑定账号、连接修订、工具描述、完整参数、会话选择修订和执行范围摘要。API 重新核验归属、连接状态和范围，消费一次性审批后，先提交 `dispatching` 回执再发请求。外部发送不自动重试；重复批准不会二次发送。批准与撤权以事务顺序为界：已提交派发的动作不能靠之后断开连接撤回；之后的动作会被拒绝。

- 待批准最多 15 分钟；模型网关令牌在本轮完成后拒绝新请求，最长 24 小时失效。
- 外部调用总限 45 秒。进程中断遗留的 `dispatching` 超过两分钟，在查询回执时转为 `unknown`；不重发。未知结果应先到服务方核对。
- 同一轮相同账号、工具和参数请求返回同一回执；想再次执行相同动作，必须开启新轮次并重新批准。
- 页面显示完整操作参数和账号；结果持久保存，刷新后可查看。普通会话原有外部 MCP 待批操作不自动开启新的模型轮次；方法 MCP 与包内脚本保持原 tools/call，批准并完成后原轮次继续。
- 本地断开删除平台保存的凭据；Bearer 方式不保证服务端凭据已被吊销，页面提示到服务方撤销。
- JSON Schema 只允许文档内引用，解析器无外部资源 Registry；禁止通过 `$ref` 绕过出站目录。

## 技能包与自动发现扩展（2026-11-13）

普通聊天／工作默认 `skill_mode=auto`：每轮开始由 API 列出当前账号所有启用技能的名称、用途、ID、版本及缺失工具，runner 经现有 app-server 协议交给 Codex；正文和附件不在目录输入里。模型按任务决定是否调用 `skill_read`。本次能力可以改成 `explicit`，最多选择 10 项，空集合表示禁用本会话技能；清空按钮同时切换为 explicit。旧选择有明确技能列表时保留 explicit，未选择过技能的旧会话使用 auto；外部工具旧授权不自动扩大。

自动目录暂最多 100 项，超过时明确要求限制会话范围，不静默截取。目录本身仍有上下文成本，尚未实现语义搜索或大型市场候选检索。每轮范围持久保存在原选择表的 runtime JSON，包含技能 ID、版本摘要、修订、scope、过期时间；每次读取再验账号、范围、状态、修订与 token。新安装的技能只在下一轮加入；停用立即阻止后续读取。读取回执 `capability/skill_read` 记录版本、文件哈希、路径、scope 与偏移，不复制正文；服务重启可从 PostgreSQL 恢复。专家步骤仍由冻结契约控制，不继承普通聊天目录。

ZIP 通过 `POST /workbench/capabilities/skill-packages` 导入（请求模型 `SkillPackageCreate`）。ZIP 必须在根目录包含 UTF-8 `SKILL.md`；压缩包不超过 2 MiB，最多 256 文件、解压总量 4 MiB、单文件 512 KiB、主文件 64 KiB。拒绝链接、特殊文件、重复或越界路径、加密与损坏 ZIP。只在内存中校验和解码，不写宿主文件系统、不执行安装器。不可变文件及哈希存入现有资产 detail JSON；列表查询在 SQL 中排除文件正文，避免目录加载整批附件。该次 ZIP 增量没有新增 DDL；后续共同调用记录候选另有 0041，见上节。

`skill_files` 每页最多 50 条；`skill_read` 文本每次最多 16000 字符，返回下一偏移；PNG/JPEG 作为 MCP 图片内容返回，其它二进制保留但读取器只返回说明。相对链接使用 `relative_to` 指向当前文档，规范化后必须仍在同一技能包内。文本脚本可读作示例，不自动执行。执行能力与读取器分开：脚本执行按下文能力开关与环境约束处理；任意本地路径和额外依赖不会自动可用，不能宣称任意第三方 Skill 都完整可运行。

包存储属于 KnowBench 的账号资产；沙箱没有权威副本，新建 Pod 不需重装。远程开发 Codex 的 `~/.codex-official/skills` 与此独立。本地 WSL 宿主目录也不自动成为用户沙箱目录。用户安装并启用表示允许发现和读取这个技能包，不代表授予它声称需要的 MCP／命令／网络权限。

发布需同步 API、runner、web，提供方 Schema 与消费者锁已一起更新。滚动窗口内严格契约可能暂时不匹配，待三者就绪再验收。不导入包时可退回 #92；已有技能包资产时，#92 的旧响应模型不认识新格式，不能直接回退旧 API；优先前向修复，或先经批准导出并处理新格式资产后再回退。不删表、不自动删除用户资产。

## 安装与统一工具注册（2026-11-13 候选）

API 拥有账号安装记录、不可变包、连接凭据和工具注册；runner 拥有当前聊天轮次或方法步骤的选用与暴露准备。二者是不同 Deployment，同属 KnowBench 应用并使用同一领域账；这不意味着把外部凭据或整个注册中心复制给 Codex。Codex 只获得当前范围内的网关工具和技能简介。注册、选用、暴露、批准、执行各自独立。

方法契约真源：`app/domain/workbench/method_capabilities.py`；用 `scripts/export_method_capabilities.py` 导出 KnowLab 消费者模型与内容锁，当前序列化仍省略空字段；公共机制/C2 改造时须按新契约统一规范，历史原件只作审计证据，不继续作为旧格式执行入口。本次缺陷补丁无新增 DDL。

## 包内脚本执行（候选，需平台组件一起发布）

开关 `WORKBENCH_SKILL_SCRIPTS_ENABLED` 默认关闭。启用前需重建 sandbox 和 provisioner，发布供给器的 Job／pod log RBAC，并通过原生 `platform-check OBJECT=sandbox-platform/provisioner` 的真实集群执行探针。仅更新 KnowBench 镜像不足以启用脚本。API、runner 均需已有供给器 URL 与服务令牌；这些凭据绝不交给脚本。

安装资产含 `.py`、`.sh`、`.js`、`.mjs` 或 `.cjs` 时，当前选中范围自动获得该技能的 `skill_run` 工具别名；路径枚举来自固定包文件。模型不能通过参数提交另一份代码或任意宿主命令。读取正文后，模型按技能说明选入口及参数，用户在同一操作卡批准。

执行顺序：API 验证 scope 和包修订 → 持久记录 dispatching → 供给器用调用 ID 提交独立 Kubernetes Job → runner 查询结果并写回原调用账 → 原 tools/call 返回实际结果。Task／Attempt／Interaction 仍是原有账，不新建工作流状态机。聊天／工作和方法步骤共用包与执行接口，方法依然有更严格的冻结范围。

每个账号同一时刻占一个执行位置；Job 使用镜像内 Python 3、Bash、Node，非 root、只读根文件系统、默认 seccomp、丢弃全部 capabilities，不挂模型 key、MCP 凭据、用户 PVC、本地 link 或 ServiceAccount token。输入只含所选技能包、参数和标准输入，通过该 Job 所有的临时 Secret 交付。所有输入卷均为必需项，部分交付不能启动脚本。独立网络策略拒绝全部出入站；不可访问云端元数据、Kubernetes API、其它容器或用户本地项目。

工作目录为包根目录，相对引用保持不变；输出写到 `outputs/`（也由 `SUNMOON_OUTPUT_DIR` 指定）。脚本执行上限 30 秒，Job 含拉取与准备总上限 90 秒，内存 256 MiB、CPU 500m、临时内存盘 32 MiB；stdout/stderr 各保留 64 KiB；最多返回 32 个普通文件、合计 512 KiB，拒绝输出符号链接和特殊文件。结果包含退出码、超时、截断和产物缺失说明，不能把有退出错误的运行当作成功。

完整结果先入库，再删除临时 Job；文件二进制不会注入模型上下文，工具结果只提供元信息和下载地址。`GET /workbench/capability-calls/{id}/artifacts/{index}` 再验账号归属并作为附件下载。运行卡可停止脚本；停用技能、scope 轮换、方法取消或授权到期会由 runner 请求停止。集群失联时不能声称已停止，但 Job 自身截止时间仍有效。结果未知不自动重跑；重复审批不会再次提交。已完成 Job 的临时资源保留上限 15 分钟，正常收取后立即删除；这不清理用户资产或历史回执。

这里的云端脚本执行是明确的能力，不是本地 link 离线后的备用通道。脚本无网络、不会自动 pip/npm 安装、不能直接使用本地项目路径。当前提供参数与小文本标准输入，不宣称已实现任意用户文件挂载或所有第三方依赖。需要这些能力时应扩展明确的执行环境和输入绑定，不能暗中放宽本容器权限。

当前脚本没有连接器调用入口。按 2026-11-14 新分类，工具方法不调用其它方法；C5 由专家编排“连接器工具方法读取 → 脚本工具方法计算 → 发送工具方法”，各步通过输入／产物绑定交接。脚本继续无网络、无外部账号凭据、无方法调用令牌；不再以脚本运行中请求连接器为目标。各个外部动作分别核权和审批，取消、恢复与结果未知由通用调用机制处理。

供给器契约真源是平台仓 `sandbox-platform/provisioner/script_contract.py`，通过 `export_script_contract.py` 导出本应用 `script_contract_generated.py` 与摘要锁。内部调用分为短请求的提交／查询／停止，不在 HTTP 请求中等待整个脚本。回执恢复复用 runner 的轮询；失败不影响正常任务租约续期。

## Skill 依赖与方法步骤范围（2026-11-13 候选补齐）

安装声明中的 `tool_requirements` 使用 MCP 服务 URL 与工具名，不绑定作者的账号，可先安装、后连接。旧 `dependencies` 精确账号工具键仍按原绑定处理，撤销后不自动改用另一个账号。设置页与本次能力面板共用依赖状态展示；自动目录只提供依赖数量及缺项数量，读取 SKILL.md 时再返回依赖详情与当前已经选定的工具键，不向每轮输入注入全部账号候选。

作者选择 Skill 时，将其 `required_tools` 一并写进该步骤的工具声明；对应工具在技能移除前不能单独删掉。依赖未能解析或同一版本/摘要存在不同安装依赖时，作者目录标明不可选，避免静默选择某份声明。方法运行时仍由使用者绑定自己的一个账号，每次校验所选技能的真实依赖不能越过冻结范围；声明依赖不构成操作批准。此处现有省略空字段的行为将在公共机制/C2 改造时一并收敛，不作为新开发继续保留兼容的理由。

脚本停止接口在删除带 UID 前置条件的原 Job 后，检查原执行的 Pod 已终止；超时返回未确认，不提前宣称停止，也不误删同名的新执行。结果日志按 Job UID 取 Pod，避免读入后继执行的结果。

## 正式方法来源的运营许可证据目录（2026-11-15 候选）

`WORKBENCH_SOURCE_LICENSES` 是 JSON 数组，默认 `[]`。配置真源沿用现有运营部署配置；模型、浏览器、安装请求及资产 `detail.execution_license_basis` 均不能写入或替代这个目录。领域模型在 `app/domain/workbench/source_licenses.py`，由 `core/config.py` 启动时解析并检查冲突。这里没有新增管理接口、数据库主档或跨应用契约字段。

每项必须明确填写以下内容，不靠省略字段授予任何权利：

| 字段 | 含义与核验 |
| --- | --- |
| `record_id`、`revision` | 运营核验记录的稳定编号与正整数修订；同编号或同主体／来源五元组重复配置即拒绝启动，撤销记录也不例外 |
| `subject` | 精确的认证用户 subject，不支持通配符，不自动扩展到其它作者或同组织账号 |
| `source` | `kind`、`source`、`version`、`digest`、`entry` 五项全部精确匹配；当前种类仅 MCP、Skill 指令和 Skill 脚本 |
| `rights` | `execute` 与 `deliver` 两个独立、必填的布尔值；交付权不能推导执行权 |
| `status`、`valid_from`、`expires_at` | 状态为 `active` 或 `revoked`；起止带时区、终点晚于起点，仅在起点含、终点不含的区间生效 |
| `evidence` | 运营核验的稳定文档／审计 `reference` 与 `sha256:` 内容摘要；校验引用与摘要格式，不联网获取、执行或自动判定证据的法律效力 |

来源目录仍先核安装归属、资产修订及可用状态；MCP 还必须匹配既有可信操作定义。执行许可缺失、未生效、过期、撤销或 `execute=false` 时，来源的 `license_basis` 返回 `pending`，正式验证保留来源缺项。有效时，服务端生成记录编号、修订及**整条记录规范摘要**组成的引用；包括证据、期限或权利在内的任何改动都改变引用，即使误漏修订号也不能沿用旧选择。界面回传值只用于与当前服务端结果精确比较，不能自证许可；证据原文、文档位置和证据摘要不随来源响应暴露。

验证受理与首次冻结登记重新核验当前目录，安装升级、来源变更、主体变化及许可变化不能靠旧验证回执通过。已经登记的精确版本重复提交／查询仍返回历史登记事实，不修改历史许可引用；历史登记不是当前运行或交付许可，后续正式执行与交付入口还必须消费当前权限。平台来源仍因缺少经过核验的实现记录而拒绝；工具描述摘要不是平台代码版本，也不承诺远端 MCP 代码被冻结。

编排方法本身没有直接实现来源；当前编译仅核依赖版本已经登记及其精确摘要，不证明依赖此刻仍获许可。后续正式派发须逐依赖重新核对有效执行权，不能凭编排方法 `source=null` 或既往登记绕过。

当前不配置任何真实许可证据，不启用交付，也不把目录中有配置称作已核定真实许可。`deliver` 仅独立保存与纳入摘要，本批没有交付消费者；它不开放再分发、跨作者转授权或上架资格。正式验证执行器仍待实现，目录匹配只消除对应来源缺项，不能产生通过回执。测试中的许可证据与完成回执均为明确标注的合成夹具。

## 私有孵化中读取 KnowBase 资料

正式方法声明资料 ID、版本、用途和资源范围。仅当受信操作目录将 `read_method_input` 映射到 `KNOWBASE_INTERNAL_URL` 对应的数据 MCP、有工作台签名密钥且来源许可有效时，私有孵化中的宿主或模型试跑才能请求读取。工具参数只有 `material_id` 和 `version_no`。每层方法身份取自已受理的冻结快照、精确依赖、当前 Task 和共同调用账。

1. 宿主或模型提出动作后，本人通过 `GET /workbench/capability-calls/{call_id}/knowbase-read` 查看调用入口（`caller` 的取值为 `host` 或 `model`）、用途、资料、版本、完整方法调用链和 `subject_digest`。草稿根方法按定义摘要识别，已登记的子方法同时核对冻结版本和定义摘要。
2. 本人向同一地址 POST 所见摘要、带时区的 `expires_at`，并选择已有的本任务 `grant_id` 或提交所选原件的完整 `sha256`。后者由 KnowBase 按任务、资料和版本签发仅供方法使用的父授权。保存返回的 `grant_id` 和叶子 `method_call_id`。
3. 用户再沿原有动作审批确认本次执行。KnowBase 以签名声明和持久授权核对精确调用链，在取原件前后复核授权。成功回执给出原文、完整 SHA-256、资料版本、父授权与叶子调用 ID。当前支持本人已向 KnowBench 展示、最多 16,000 字节的 UTF-8 文本原件。
4. 本人可用 `DELETE /workbench/knowbase-method-reads/{grant_id}/{method_call_id}` 撤销本次读取。撤销父授权会使其下全部读取失效。相同授权可幂等确认，同一调用变更授权条件需重新发起调用。

模型入口仅开放给允许模型试跑的直接工具方法。预览、授权和实际批准都核对同一条已观察到的线程、轮次和工具调用，成功回包的结构化数据与可读文本均由核验过的原件和出处生成。读取被拒时模型收到失败状态。宿主入口还支持已冻结的递归依赖。

旧委托的 `accepted_plan` 身份继续用于原有一步委派。正式孵化需要本人确认上面的真实方法调用链。浏览器入口与普通用户委托按专家方案的后续阶段接入。
