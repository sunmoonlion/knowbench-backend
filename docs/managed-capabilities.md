# 受管连接、技能与本次能力

三个入口由本地 Jenkins #92 发布；安装模块、方法步骤与脚本执行组件已随 #93 发布，用户脚本执行开关仍关闭。首批评审修复与 KnowLab 作者入口限制已于 2026-11-14 经 Jenkins #94 发布，标签 `release-20261114-1`；下面的工具登记、调用身份、操作契约和方法权限改造仍未发布。连接与凭据存放在 API 的数据库；runner 负责本轮准备，沙箱里的 Codex 接收限定工具清单和短期会话凭证。外部服务的 Bearer 凭据只在 API 解密使用。

## 评审修复（2026-11-14 已随 #94 发布）

- 外部适配器区分连接/握手阶段未执行、收到匹配的协议/工具结果、派发后结果未知。读超时、断流、写出异常、HTTP 代理错误、超限或坏回包记 `unknown`，不自动重发。明确工具失败也不保证已经发生的部分副作用被回滚。
- 连接修订变化、停用或缺失时，聊天/工作排除有问题的能力并明确提示，其余交流继续；不自动把旧账号/工具选择改成新授权。方法缺必需能力仍暂停。旧审批继续核连接版本、完整参数和执行范围，更新凭据不能沿用旧审批。
- `turn/completed` 按持久化 session/turn 关闭范围，不要求 runner 内存还保留 scope；晚到的旧 turn 不能关闭新 turn。runner 接管沙箱及连接重建先撤销旧范围，Skill 读取和新工具请求都拒绝。正常聊天完成前已提交的精确审批可在原时限内由用户决定，但接管/重连使旧范围 aborted，旧审批也不能再执行。
- 没有安装资产、没有历史能力 runtime 且没有活动方法的普通会话走元数据快路径，不新增能力范围、不加资产行锁、不为能力准备调用 `thread/read`。方法场景及曾配置能力的会话继续核对范围。
- 仍按轮次换令牌，稳定 MCP 配置不是本补丁已实现功能；后续必须将连接身份与受信的 turn/调用身份分开，不能把令牌延长有效期后直接复用到下一轮。

所有者已明确新开发不要兼容：后续公共机制/C2 改造删除旧执行分支；有实际数据才作一次性迁移，不长期双读双写。2026-11-13 夜三张能力表均为空，相关工作稿/专家草稿/市场版本/委托无方法能力字段。此检查不代表其它旧类型都无人使用，发布前复核。

## 工具登记改造候选（2026-11-14，尚未发布）

API 内的 `application/workbench/tool_registry.py` 统一投影平台内置定义、knowbase 目录和用户 MCP 发现快照。平台描述已移至 `domain/workbench/platform_tools.py`；现有平台 `tools/list`、连接安装/刷新/更新凭据，以及外部工具和隔离脚本的调用检查均使用共同登记结构。没有新建第二份数据库主档，也没有把全量目录自动暴露给每个模型会话。

登记身份由来源、服务和工具名确定，不包含用户连接 ID；描述和参数 Schema 的内容摘要单独标识发现快照。同一服务的两个账号共用定义身份，归属、连接修订与执行授权仍分别检查。摘要只证明描述一致，不证明远端实现代码固定。描述不可原地修改；重复登记、同一 MCP 暴露范围内的重名、冻结定义与当前定义不一致均拒绝。每次外部调用只检查所选工具，不重新验证账号全部工具的 Schema。

远端 annotations、伪造的操作契约或免审批字段不成为登记的权限事实；平台原有展示注解保留，也不作为业务授权依据。**本增量仅完成共同登记的基础接入：可信连接器操作映射、六要素权限字段、共同审批与 call_id 尚未完成，C2 不能关闭，作者能力入口限制继续保留。**外部调用仍按现有规则逐次审批，脚本执行开关保持关闭。无数据库迁移、公开响应格式或前端变更；独立复审的首批修复已按隔离候选随 #94 发布，未夹带此增量。

## 共同调用身份候选（2026-11-14，尚未发布）

平台 MCP 和受管 MCP 共用 `application/workbench/tool_invocation.py` 的来源核验：以请求元数据定位 runner 已持久化的 `item/started` 事件，核账号、沙箱、会话、线程、轮次、工具服务、工具名及完整参数。元数据本身不授予权限；未观察到的调用、跨服务重放、参数改变、已完成轮次均拒绝。删除了“账号没有动态任务便免核来源”的平台入口分支。

受管入口还核当前范围绑定的真实轮次、用户接受记录或当前方法 Attempt；Skill 正文/附件、文件列表与动作结果查询也经过同一核验。runner 的事件、轮次绑定与接受记录有正常先后差异，核验会在无行锁且未执行工具时有界等待，超时拒绝。请求进入审批事务后再做一次不等待的核验。

受管调用以宿主的 session/thread/turn/server/call 身份去重，完整参数与授权摘要单独核对：同一次调用重试返回原记录；不同调用即使参数相同也需要新的审批；同一调用身份改变参数拒绝。来源快照保存在既有调用记录内，浏览器响应不增加内部执行身份。批准时重核线程、轮次、连接及原有条件；正常轮次结束后已提出的精确审批仍可在原期限内决定，换线程、撤权或重连后不可执行。缺少新来源快照的旧审批不能继续派发，切换前须核对并使其失效，不保留旧批准执行分支。

此增量没有新建调用账或修改公开响应契约，也没有实现平台计算/读数与受管调用的全部统一落账。业务权限映射、父子委派、正式方法准入、共同审批策略、稳定 MCP 配置及 C3–C6 仍待完成。配置仍逐轮换令牌；作者入口和脚本开关维持原状态。定向回归 130 项通过（真实 PostgreSQL、runner/本机 WebSocket、两个 MCP HTTP 入口、脚本、契约及分层），Ruff 通过，Pyright 零错误；未重跑本增量全量。发布前仍需最终全量、独立复审及固定 Codex 的实际协议验证。

## 外部操作契约候选（2026-11-14，尚未发布）

外部 MCP 不再仅凭审核 URL、工具发现和用户逐次批准执行。运营配置 `WORKBENCH_CAPABILITY_OPERATIONS` 是可信适配定义的唯一来源；`domain/workbench/tool_operations.py` 校验定义，API 在登记投影、选择、准备、调用和批准派发时消费。MCP annotations、模型参数和用户安装请求不能提供或替换这些权限事实。

每项定义包含以下字段，不含用户凭据或当前批准：

| 字段 | 实际检查 |
| --- | --- |
| `service_url`、`tool_name`、`descriptor_digest` | 精确绑定已审核服务与发现快照；摘要由 `ToolRegistration.discover("mcp", url, descriptor).descriptor_digest` 生成，不是远端实现版本承诺 |
| `capability_ref`、`version`、`operation` | 平台核定的业务操作契约及版本，不以工具名称推测业务含义 |
| `effect` | 只接受 `read`、`write`、`send`；所有操作仍逐次审批，可信只读不等于已获得任务范围授权 |
| `resources[]` | 显式声明资源角色与参数路径；无参数资源时显式 `[]`，不能漏字段 |
| 资源的 `resource_kind`、`resource_role`、`argument_path`、`cardinality` | 当前责任域为 `connector`；路径只逐层取对象字段，终值为一个字符串或非空字符串数组；不执行表达式或通配匹配 |
| 资源的 `allowed_values` | 可选的平台精确值集合上限；省略只表示平台未额外收窄，用户仍须批准具体动作；空集合、重复值和未知条件拒绝 |

例如发送工具的 `to` 参数可绑定为 `{"resource_role":"recipients","argument_path":["to"],"cardinality":"many","allowed_values":["approved@example.test"]}`。必须按服务真实语义核定全部资源字段（包含可能的抄送、密送、查询范围等）；复杂查询、目录层级或别名不能假装成通用精确匹配，需要专门适配。工具名相同不代表适配成立，刷新后的描述摘要变化也须重新核定。

新配置为 JSON 数组，默认 `[]`。端点不在 `WORKBENCH_CAPABILITY_MCP_URLS`、重复绑定、未知字段或不支持的条件均在配置解析期拒绝。配置由原有部署配置真源提供，API 与 runner 同批更新；没有新增管理接口或另一份数据库策略主档。没有操作定义时仍可安装连接、发现工具和保留记录，但不能选用或执行该工具；本次能力显示原因，已选工具可移除。聊天准备排除不可用工具后继续，方法缺必需项则拒绝准备。

准备时冻结操作定义摘要；新调用核真实宿主身份，再解析资源和平台上限，超范围请求不生成审批。实际操作、资源、数据去向及完整参数摘要保存在已有调用记录中并参与原审批摘要。即使是读取，发往服务的查询参数也记录为数据外发。批准前再次核当前定义与精确请求；移除、收窄、扩大或升级定义均使旧批准不能继续执行，仍可拒绝该请求。旧记录缺操作快照不能现场补造后派发。`tools/list` 和 Skill 正文中的已选依赖提示也排除操作定义失效的工具；已有模型上下文无法追溯删除，实际调用仍会拒绝。

这只是 C2 的可信外部操作映射与平台资源上限：**尚未接入方法层 `access_requirements`、父子委派范围、资源端账号权限、任务范围只读授权、平台内置工具的共同业务策略和统一调用账。**逐次审批仍不代替这些后续权限检查；作者入口保持关闭，脚本开关保持关闭。新配置没有部署，真实供应商语义未验收；没有数据库迁移和公开响应结构变更。

最终定向回归 171 项通过、无失败或跳过（两个 MCP 入口、真实 PostgreSQL/HTTP/runner、Skill、配置、契约及分层）；前端能力组件/契约 16 项通过，Ruff/Pyright/TypeScript/ESLint/i18n 检查通过。未跑本增量全量，未做真实供应商或 Codex 协议补验；发布仍须独立复审及完整发布门。

## 方法权限声明与确认候选（2026-11-14，尚未发布）

`StepContract`（现有固定步骤与方法契约共用的载体）新增独立的 `access_requirements`。`managed_capabilities.tools` 仅保存服务 URL、工具名及 `requirement_id` 引用；不能再用地址加名称替代权限声明。Skill 安装的 `tool_requirements` 和包中 `required_tools` 仍是技术依赖，不要求普通聊天／工作经过孵化。

当前可执行的权限结构为：稳定要求编号、可信 `capability_ref` 和版本、操作集合、按资源种类与角色分组的精确值集合，以及外发地址、允许外发的顶层参数字段和用途。当前仅支持 connector、无条件必需、缺项暂停；通配符、表达式、动态来源、其它资源种类不会被解释为已支持。参数字段限制不能代替资料来源及产出许可追踪，后者仍待通用调用树和资料绑定实现。工具引用必须有效，未绑定的权限声明及重复编号拒绝。

流程是：冻结方法声明 → 匹配运营核定的操作定义 → 用户在“本次能力”查看操作、资源、外发去向和用途，选择自己的账号并点击“确认权限并保存绑定” → 按不可伪造的当前方法上下文保存权限确认及账号修订 → runner 准备时冻结到本轮工具范围。确认不自动批准任何外部动作；所有外部调用，包括读取，仍逐次审批。

调用前同时检查平台上限、方法声明、已确认范围、具体参数及真实方法 Attempt；超范围请求不创建审批单。批准派发前再核冻结权限、当前操作映射和请求。缺少确认不从作者声明补造；确认或策略失效时，既有工具目录也排除该工具。方法范围说明提供给模型，但真正核权在 API，不能靠模型遵守提示词。批准中的范围与操作快照写入既有调用记录，不新建第三本账。

契约真源是 `method_capabilities.py`，导出 KnowLab 的模型、Schema 和摘要锁；动态方法运行 Schema、作者方法 Schema、消费锁及网页响应契约同步生成。KnowLab 仍拒绝保存、导入、编译和发布带能力绑定或权限声明的新方法，本增量不重新开放作者入口。旧无权限引用的绑定不留运行兼容分支；发布前复核实际数据，必要时执行一次性转换，原记录仅保留为审计证据。

初批仅实现现有 Task/Attempt/步骤上下文的根范围；后续候选已加入下面的持久父子授权。资源方实时权限、KnowBase/本地工作区的子范围、三类方法孵化准入、自动提前绑定、只读范围审批复用仍待后续。没有实际父调用时不接受模型自报父 ID，不凭用户拥有其它账号扩大范围。脚本开关仍关闭。

## 共同调用记录候选（2026-11-14，尚未发布）

迁移 `20261114_0041` 将既有 `workbench_capability_calls` 改名为 `workbench_calls`，原 ID、摘要、批准关联和结果证据保留。平台工具、KnowBase 中继、外部 MCP 和 Skill 脚本都写入同一张表；计算记录、读数记录继续承担业务证据职责，调用回包保存其引用，不复制计算逻辑。`source_asset_id` 指安装来源，`connection_id` 只指连接账号；脚本从存储层开始就是空连接。

每次调用保存真实宿主调用键、登记 ID 与描述摘要。平台 MCP 也在派发前提交记录：同一宿主请求只执行一次，重复请求返回已保存的回包；尚无回包时明确拒绝重复派发。返回的 MCP `_meta` 带统一 `call_id` 和 `call_status`，业务 `structuredContent` 不变。共享恢复逻辑把超时未结算的派发记为未知，未知不自动重发；这不等于跨新调用编号的业务幂等。

有受信 Task 的调用关联一个稳定的根方法调用记录，并单独记录实际 Attempt。换执行尝试不创建第二个根调用，根状态投影现有 Task 的状态转换，不另设状态机或记费。根记录在该 Task 首次发生工具调用时创建；没有工具调用的任务仍只保留既有 Task 账，本批未实现通用方法入口即登记。普通聊天没有虚构方法父节点。父关联只由已核验的宿主上下文生成，模型不能提交父调用 ID；核权后上下文变化则拒绝落到另一件委托。

此处只完成现有根 Task 与其工具调用的持久关联，**没有完成嵌套方法展开、子方法身份、父范围交集、委派撤销传播或三类方法孵化准入**。调用记录本身不授予权限。现有方法/连接业务范围与审批仍按各入口已有检查执行，共同核权规则尚待继续收敛。能力面板只展示受管操作，方法根记录和平台工具不会被当成待批准操作。

迁移前按既有发布流程排空活动任务，盘点线上实际数据。迁移保留历史 detail 和 digest；旧待批调用转 expired，旧派发未结算转 unknown，旧 runtime 作废。旧历史键只作证据，不继续执行或补造权限。迁移完成后 API 与 runner 必须同时使用新代码，不能混跑仍访问旧表的实例。该候选需重建 API/runner 镜像；本批无网页契约变化。已有方法/平台新记录时禁止向 0040 降级，使用前向修复；不能为了回退丢调用证据。迁移尚未在生产执行。

## 授权与执行

注册／工具发现、会话选择、模型暴露、操作批准、实际执行是不同阶段。选择保存使用期望修订比较交换，冻结资产版本；资产停用、更新凭据或刷新工具后，旧选择必须重新核对。默认偏好不改变授权版本；刷新不会把新工具加到旧选择。

普通会话的外部 MCP 工具先登记待批操作；方法步骤的外部 MCP 调用和所有包内脚本调用则以 SSE 等待审批及真实结果后返回。工具描述和注解按实际执行语义提供，不把远程写操作标成只读。固定 Codex 的原生批准不替代平台的操作批准。首期所有外部调用（包含读取）都逐次确认。

批准绑定账号、连接修订、工具描述、完整参数、会话选择修订和执行范围摘要。API 重新核验归属、连接状态和范围，消费一次性审批后，先提交 `dispatching` 回执再发请求。外部发送不自动重试；重复批准不会二次发送。批准与撤权以事务顺序为界：已提交派发的动作不能靠之后断开连接撤回；之后的动作会被拒绝。

- 待批准最多 15 分钟；模型网关令牌在本轮完成后拒绝新请求，最长 24 小时失效。
- 外部调用总限 45 秒。进程中断遗留的 `dispatching` 超过两分钟，在查询回执时转为 `unknown`；不重发。未知结果应先到服务方核对。
- 同一轮相同账号、工具和参数请求返回同一回执；想再次执行相同动作，必须开启新轮次并重新批准。
- 页面显示完整操作参数和账号；结果持久保存，刷新后可查看。普通会话原有外部 MCP 待批操作不自动开启新的模型轮次；方法 MCP 与包内脚本保持原 tools/call，批准并完成后原轮次继续。
- 本地断开删除平台保存的凭据；Bearer 方式不保证服务端凭据已被吊销，页面提示到服务方撤销。
- JSON Schema 只允许文档内引用，解析器无外部资源 Registry；禁止通过 `$ref` 绕过出站目录。

## 技能包与自动发现扩展（2026-11-13）

普通聊天／工作默认 `skill_mode=auto`：每轮开始由 API 列出当前账号所有启用技能的名称、用途、ID、版本及缺失工具，runner 经现有 app-server 协议交给 Codex；正文和附件不在目录输入里。模型按任务决定是否调用 `skill_read`。本次能力可以改成 `explicit`，最多选择 10 项，空集合表示禁用本会话技能；清空按钮同时切换为 explicit。旧选择有明确技能列表时保留 explicit，未选择过技能的旧会话使用 auto；外部工具旧授权不自动扩大。

自动目录暂最多 100 项，超过时明确要求限制会话范围，不静默截取。目录本身仍有上下文成本，尚未实现语义搜索或大型市场候选检索。每轮范围持久保存在原选择表的 runtime JSON，包含技能 ID、版本摘要、修订、scope、过期时间；每次读取再验账号、范围、状态、修订与 token。新安装的技能只在下一轮加入；停用立即阻止后续读取。读取回执 `capability/skill_read` 记录版本、文件哈希、路径、scope 与偏移，不复制正文；服务重启可从 PostgreSQL 恢复。专家步骤仍由冻结契约控制，不继承普通聊天目录。

ZIP 通过 `POST /workbench/capabilities/skill-packages` 导入（请求模型 `SkillPackageCreate`）。ZIP 必须在根目录包含 UTF-8 `SKILL.md`；压缩包不超过 2 MiB，最多 256 文件、解压总量 4 MiB、单文件 512 KiB、主文件 64 KiB。拒绝链接、特殊文件、重复或越界路径、加密与损坏 ZIP。只在内存中校验和解码，不写宿主文件系统、不执行安装器。不可变文件及哈希存入现有资产 detail JSON；列表查询在 SQL 中排除文件正文，避免目录加载整批附件。该次 ZIP 增量没有新增 DDL；后续共同调用记录候选另有 0041，见上节。

`skill_files` 每页最多 50 条；`skill_read` 文本每次最多 16000 字符，返回下一偏移；PNG/JPEG 作为 MCP 图片内容返回，其它二进制保留但读取器只返回说明。相对链接使用 `relative_to` 指向当前文档，规范化后必须仍在同一技能包内。文本脚本可读作示例，不自动执行。执行能力与读取器分开：脚本执行按下文能力开关与环境约束处理；任意本地路径和额外依赖不会自动可用，不能宣称任意第三方 Skill 都完整可运行。

包存储属于 KnowBench 的账号资产；沙箱没有权威副本，新建 Pod 不需重装。远程开发 Codex 的 `~/.codex-official/skills` 与此独立。本地 WSL 宿主目录也不自动成为用户沙箱目录。用户安装并启用表示允许发现和读取这个技能包，不代表授予它声称需要的 MCP／命令／网络权限。

发布需同步 API、runner、web，提供方 Schema 与消费者锁已一起更新。滚动窗口内严格契约可能暂时不匹配，待三者就绪再验收。不导入包时可退回 #92；已有技能包资产时，#92 的旧响应模型不认识新格式，不能直接回退旧 API；优先前向修复，或先经批准导出并处理新格式资产后再回退。不删表、不自动删除用户资产。

## 安装与统一工具注册（2026-11-13 候选）

API 拥有账号安装记录、不可变包、连接凭据和工具注册；runner 拥有当前聊天轮次或方法步骤的选用与暴露准备。二者是不同 Deployment，同属 KnowBench 应用并使用同一领域账；这不意味着把外部凭据或整个注册中心复制给 Codex。Codex 只获得当前范围内的网关工具和技能简介。注册、选用、暴露、批准、执行各自独立。

设置 → 技能 → 安装技能提供公开 GitHub 仓库／目录／SKILL.md 链接预览；用户核对名称、用途、正文和脚本提示后安装。预览固定提交 SHA，安装再次核对包摘要，保存整个目录和来源。保留 Markdown／ZIP 高级入口；停用与卸载都撤销后续使用，卸载保留历史回执，再安装产生新资产。暂不支持私有 Git 仓库、带斜杠的分支链接和自动依赖安装；可用完整 ZIP 导入。

接口：`POST /workbench/capabilities/skill-sources/preview`、`POST /workbench/capabilities/skill-sources/install`。来源端只访问公开 GitHub API 与固定 codeload 地址，公网 DNS 固定连接、TLS 校验、拒绝重定向；不运行仓库安装脚本。

方法独立使用 `StepContract.access_requirements` 声明业务权限；`managed_capabilities` 保存引用权限编号的工具绑定及技能的名称／版本／摘要。作者目录来自 KnowBench 已安装资产，经受保护的内部接口供 KnowLab 查询，不携带账号凭据或正文。选择界面隐藏摘要维护细节。使用者绑定自己的资产，API 验证声明、版本、唯一账号和步骤上下文；每次调用再检查 task、attempt、step、接受的计划与撤权。执行场景参数为 `ExecutionScene.CONVERSATION` / `METHOD`，不再使用 expert 布尔开关；现有会话分类仍有 expert（线上计数为 54 件），属于后续一次性迁移范围，不能简单删除，也不再为它保留长期兼容运行分支。

方法契约真源：`app/domain/workbench/method_capabilities.py`；用 `scripts/export_method_capabilities.py` 导出 KnowLab 消费者模型与内容锁，当前序列化仍省略空字段；公共机制/C2 改造时须按新契约统一规范，历史原件只作审计证据，不继续作为旧格式执行入口。本次缺陷补丁无新增 DDL。

## 包内脚本执行（候选，需平台组件一起发布）

开关 `WORKBENCH_SKILL_SCRIPTS_ENABLED` 默认关闭。启用前需重建 sandbox 和 provisioner，发布供给器的 Job／pod log RBAC，并通过原生 `platform-check OBJECT=sandbox-platform/provisioner` 的真实集群执行探针。仅更新 KnowBench 镜像不足以启用脚本。API、runner 均需已有供给器 URL 与服务令牌；这些凭据绝不交给脚本。

安装资产含 `.py`、`.sh`、`.js`、`.mjs` 或 `.cjs` 时，当前选中范围自动获得该技能的 `skill_run` 工具别名；路径枚举来自固定包文件。模型不能通过参数提交另一份代码或任意宿主命令。读取正文后，模型按技能说明选入口及参数，用户在同一操作卡批准。

执行顺序：API 验证 scope 和包修订 → 持久记录 dispatching → 供给器用调用 ID 提交独立 Kubernetes Job → runner 查询结果并写回原调用账 → 原 tools/call 返回实际结果。Task／Attempt／Interaction 仍是原有账，不新建工作流状态机。聊天／工作和方法步骤共用包与执行接口，方法依然有更严格的冻结范围。

每个账号同一时刻占一个执行位置；Job 使用镜像内 Python 3、Bash、Node，非 root、只读根文件系统、默认 seccomp、丢弃全部 capabilities，不挂模型 key、MCP 凭据、用户 PVC、本地 link 或 ServiceAccount token。输入只含所选技能包、参数和标准输入，通过该 Job 所有的临时 Secret 交付。所有输入卷均为必需项，部分交付不能启动脚本。独立网络策略拒绝全部出入站；不可访问云端元数据、Kubernetes API、其它容器或用户本地项目。

工作目录为包根目录，相对引用保持不变；输出写到 `outputs/`（也由 `SUNMOON_OUTPUT_DIR` 指定）。脚本执行上限 30 秒，Job 含拉取与准备总上限 90 秒，内存 256 MiB、CPU 500m、临时内存盘 32 MiB；stdout/stderr 各保留 64 KiB；最多返回 32 个普通文件、合计 512 KiB，拒绝输出符号链接和特殊文件。结果包含退出码、超时、截断和产物缺失说明，不能把有退出错误的运行当作成功。

完整结果先入库，再删除临时 Job；文件二进制不会注入模型上下文，工具结果只提供元信息和下载地址。`GET /workbench/capability-calls/{id}/artifacts/{index}` 再验账号归属并作为附件下载。运行卡可停止脚本；停用技能、scope 轮换、方法取消或授权到期会由 runner 请求停止。集群失联时不能声称已停止，但 Job 自身截止时间仍有效。结果未知不自动重跑；重复审批不会再次提交。已完成 Job 的临时资源保留上限 15 分钟，正常收取后立即删除；这不清理用户资产或历史回执。

这里的云端脚本执行是明确的能力，不是本地 link 离线后的备用通道。脚本无网络、不会自动 pip/npm 安装、不能直接使用本地项目路径。当前提供参数与小文本标准输入，不宣称已实现任意用户文件挂载或所有第三方依赖。需要这些能力时应扩展明确的执行环境和输入绑定，不能暗中放宽本容器权限。

当前脚本没有连接器调用入口。按 2026-11-14 新分类，工具方法不调用其它方法；C5 由专家编排“连接器工具方法读取 → 脚本工具方法计算 → 发送工具方法”，各步通过输入／产物绑定交接。脚本继续无网络、无外部账号凭据、无方法调用令牌；不再以脚本运行中请求连接器为目标。各个外部动作分别核权和审批，取消、恢复与结果未知由通用调用机制处理。

供给器契约真源是平台仓 `sandbox-platform/provisioner/script_contract.py`，通过 `export_script_contract.py` 导出本应用 `script_contract_generated.py` 与摘要锁。内部调用分为短请求的提交／查询／停止，不在 HTTP 请求中等待整个脚本。回执恢复复用 runner 的轮询；失败不影响正常任务租约续期。

## Skill 依赖与方法步骤范围（2026-11-13 候选补齐）

安装声明中的 `tool_requirements` 使用 MCP 服务 URL 与工具名，不绑定作者的账号，可先安装、后连接。旧 `dependencies` 精确账号工具键仍按原绑定处理，撤销后不自动改用另一个账号。设置页与本次能力面板共用依赖状态展示；自动目录只提供依赖数量及缺项数量，读取 SKILL.md 时再返回依赖详情与当前已经选定的工具键，不向每轮输入注入全部账号候选。

作者选择 Skill 时，将其 `required_tools` 一并写进该步骤的工具声明；对应工具在技能移除前不能单独删掉。依赖未能解析或同一版本/摘要存在不同安装依赖时，作者目录标明不可选，避免静默选择某份声明。方法运行时仍由使用者绑定自己的一个账号，每次校验所选技能的真实依赖不能越过冻结范围；声明依赖不构成操作批准。此处现有省略空字段的行为将在公共机制/C2 改造时一并收敛，不作为新开发继续保留兼容的理由。

脚本停止接口在删除带 UID 前置条件的原 Job 后，检查原执行的 Pod 已终止；超时返回未确认，不提前宣称停止，也不误删同名的新执行。结果日志按 Job UID 取 Pod，避免读入后继执行的结果。
