# 受管连接、技能与本次能力（首期实现）

本说明对应 2026-11-13 三个网页入口的代码，不表示已经发布。连接与凭据统一存放在 API 的数据库；runner 负责本轮准备，沙箱里的 Codex 接收限定工具清单和短期会话凭证。外部服务的 Bearer 凭据只在 API 解密使用。

## 可用范围

- 设置 → 连接与工具：从运营方审核的 HTTPS MCP 目录添加多个账号；验证凭据并发现工具；查看参数 Schema；启停、更新工具、更新凭据、断开；默认选择仅影响之后新建的会话。
- 设置 → 技能：导入或粘贴 UTF-8 Markdown 指令，最大 64 KiB；登记名称、用途、精确版本和依赖工具；查看正文、启停、选择默认。每次导入产生不可变版本，不覆盖旧会话绑定。
- 聊天／工作 → 本次能力：选择具体连接下的工具和技能，保存用途与版本绑定，显示准备状态、缺项、待批操作和回执。设置页可返回原会话；返回不自动执行。
- 专家页复用面板，只读显示当前冻结步骤声明的平台工具。旧专家契约没有受管 MCP/Skill 绑定字段，本次不修改专家契约或替专家扩大授权。新增外部连接和 Skill 进入方法步骤仍未实现，不能把普通会话选择视为方法授权。

支持 Streamable HTTP MCP 的 JSON 和 SSE 响应（2025-06-18 / 2025-03-26），认证为无认证或 Bearer。首期没有 OAuth、任意网址输入、stdio 安装、技能 ZIP／脚本包、技能市场或 A2A。普通连接器可通过目录内的 MCP 适配服务接入；没有把尚未实现的原生 SaaS 连接器展示成可用。

## 部署输入与升级

API 与 runner 使用相同配置和原有 `WORKBENCH_CREDENTIAL_KEY`（Fernet Secret），新增：

```dotenv
# JSON 数组；精确匹配；审核后的公网 HTTPS:443 地址，禁止认证信息、查询串与片段。
WORKBENCH_CAPABILITY_MCP_URLS=["https://your-reviewed-service.example/mcp"]
# 沙箱可达的本平台受限网关地址，不是外部 MCP 服务地址。
WORKBENCH_CAPABILITY_MCP_URL=https://your-platform.example/api/mcp/capabilities
```

示例域名不是真实服务，不能直接拿来验收。目录默认空；网关默认空，未配置时页面明确提示，选择外部工具的轮次在调用模型前拒绝。通过现有配置真源发布，不能把外部密码写进环境示例、Git 或沙箱。API 出站需要解析并访问审核域名；适配器验证全部 DNS 结果均为公网 IP，连接固定解析所得 IP，TLS 证书验证和 SNI 保持原域名，不跟随重定向或系统代理。

需重建 web、API、runner 镜像，并执行线性迁移 `20261113_0040`（接 `20261106_0039`）。迁移新增资产、会话选择、操作回执三张表。先迁移再切新 API/runner/web；旧会话默认空选择，新会话在创建事务内固化默认项。开发测试完成不等于允许滚动正在运行的付费任务；发布沿用 Jenkins 和既有活动任务检查。

回滚优先回退镜像并保留新增表与回执；旧代码不使用这些表。只有已导出并确认不再需要新资产和审批历史时，才执行到 `20261106_0039` 的降级，降级会删除三张新表。隔离测试覆盖降级、重新升级以及原会话保留；没有对生产执行迁移。

## 授权与执行

注册／工具发现、会话选择、模型暴露、操作批准、实际执行是不同阶段。选择保存使用期望修订比较交换，冻结资产版本；资产停用、更新凭据或刷新工具后，旧选择必须重新核对。默认偏好不改变授权版本；刷新不会把新工具加到旧选择。

模型看到的每个外部工具是“登记待批操作”的网关。它只写平台内的审批记录，注解为非只读、非破坏、封闭范围，不把真实远程写操作标成只读。固定 Codex 的原生批准不替代平台的操作批准。首期所有外部调用（包含读取）都逐次确认。

批准绑定账号、连接修订、工具描述、完整参数、会话选择修订和执行范围摘要。API 重新核验归属、连接状态和范围，消费一次性审批后，先提交 `dispatching` 回执再发请求。外部发送不自动重试；重复批准不会二次发送。批准与撤权以事务顺序为界：已提交派发的动作不能靠之后断开连接撤回；之后的动作会被拒绝。

- 待批准最多 15 分钟；模型网关令牌在本轮完成后拒绝新请求，最长 24 小时失效。
- 外部调用总限 45 秒。进程中断遗留的 `dispatching` 超过两分钟，在查询回执时转为 `unknown`；不重发。未知结果应先到服务方核对。
- 同一轮相同账号、工具和参数请求返回同一回执；想再次执行相同动作，必须开启新轮次并重新批准。
- 页面显示完整操作参数和账号；结果持久保存，刷新后可查看。批准不自动开启新的收费模型轮次，用户继续发话后助手可读取回执。
- 本地断开删除平台保存的凭据；Bearer 方式不保证服务端凭据已被吊销，页面提示到服务方撤销。
- JSON Schema 只允许文档内引用，解析器无外部资源 Registry；禁止通过 `$ref` 绕过出站目录。

## Codex 0.155.1 的适配事实

断网真实二进制探针：`app/scripts/probes/codex_capabilities_probe.py`。合成 Responses 和 MCP 均在容器回环内，不访问模型供应商或真实账号。它验证与产品一致的长工具别名、服务名、`approvalPolicy=never`、`environments=[]`、不同轮次的认证头／白名单切换，以及显式技能正文确实到达模型请求。

新用户未预置受管 MCP 时，即使禁用也必须提供完整传输定义，否则固定版报 `invalid transport`。禁用配置使用 `enabled=false`、空工具与凭据、`required=false` 及未使用的回环丢弃端口；不发起连接。探针从没有 MCP 预配置的目录启动，并验证启用后再次禁用。

空线程尚未物化时不能直接 unsubscribe/resume。runner 先注入原有模式说明，再准备工具；没有制造一轮模型调用。分页线程的 `thread/read(includeTurns=true)` 在固定版本会返回 `list_turns is not supported yet`，现在用 metadata 的实时 idle 状态判断。非空闲或未知状态拒绝重配，不轮换正在执行的令牌。范围应用由对应 `turn/start` 回执确认，晚到的通知按 scope/turn 条件更新，不能覆盖新范围。

纯指令技能通过已选版本的正文输入交付。文件写入与 `skills/list` 成功不证明模型已读 Skill；本次探针发现 `environments=[]` 时原生 Skill 输入不加载正文，因此未以开启本地执行来绕过限制。脚本／附件包及原生扫描目录管理仍待后续实现。停用会阻止之后注入，不会删除模型已看到的历史文字；同一线程的旧文本仍可能存在。

## 契约与验证

提供方模型在 `app/domain/workbench/capability_contract.py`，请求在 `capabilities.py`，实际路由使用响应模型。导出与同步消费者锁：

```sh
cd app
.venv/bin/python scripts/export_capability_contract.py --consumer ../../knowbench-web-frontend/app
```

消费者提交 Schema、样例和 SHA-256 锁；两端测试分别核提供方漂移、实际 HTTP 响应和严格解析，拒绝意外返回凭据。

核心回归为 `test_capabilities_db.py`、`test_capability_routes_db.py`、`test_capability_mcp.py`；网页为 `capabilities.test.tsx` 与 `capability-contract.test.ts`。数据库必须显式指向以 `_tests` 结尾的隔离库。测试覆盖 owner 隔离、版本变化、默认项、凭据更新、重复批准、101 条后的去重、撤权、超时、失联恢复、迟到事件、专家边界及迁移降级再升级。真实服务业务验收与线上部署不包含在这些合成测试中。
